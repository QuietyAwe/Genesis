# Genesis

> 让 AI 角色在你的世界观里自由呼吸。

Genesis 是一个多角色沙盒模拟器。不同于传统的"一问一答"式 AI 聊天，Genesis 让多个角色在同一个舞台上自主对话、相互影响——你只需要设定场景和角色，然后看着故事自己展开。

## 痛点

**传统 AI 聊天的困境：**
- 每次只能和一个角色对话，想看角色之间的互动？手动切换，体验割裂
- 聊了 50 轮之后 AI 开始"失忆"，角色性格崩坏，前期设定全部丢失
- 想试试"如果当时角色说了别的话"？只能删掉重来，无法保留原始剧情线
- 角色设定只能写一大段自由文本，缺乏结构化引导
- 所有数据存在云端，隐私不可控

## 核心亮点

### 1. 多角色自主互动

设定多个角色后，AI 自动决定谁该说话。角色之间会互相回应、提问、争论，甚至产生你没预料到的化学反应。发言积极性可调节——有人沉默寡言，有人话痨抢答。

**应用场景：**
- 写小说时测试角色之间的对话是否自然
- TRPG 跑团前模拟 NPC 之间的互动关系
- 心理咨询场景中模拟多人社交情境

### 2. 分支时间线

对某条回复不满意？重生成会创建一个平行分支，而不是覆盖原剧情。你可以随时在分支之间切换，对比不同选择带来的剧情走向。

**应用场景：**
- "如果主角当时选了另一条路？" —— 探索多结局
- 写作时 A/B 测试不同对话风格的效果
- 保留精彩剧情线的同时尝试其他可能性

### 3. 世界观注入

世界观不是写完就扔的背景板。Genesis 支持 Lore Entry 系统：
- **全局条目**：始终注入（如世界基本法则）
- **关键词触发**：当对话中出现"血族""圣殿"等关键词时，自动注入相关设定

角色不会凭空"发明"世界观细节，而是在你设定的框架内自由发挥。

**应用场景：**
- 架空世界小说的角色行为一致性保障
- 游戏世界观测试——NPC 是否遵守世界规则
- 教育场景中模拟历史/科学情境

### 4. 智能上下文管理

长对话不会"失忆"。滑动窗口压缩机制会自动总结早期对话，保留关键信息的同时释放上下文空间。压缩阈值与你的 Context Window 设置动态绑定，不浪费一个 token。

### 5. 灵活的角色创建

三种方式，按需选择：
- **填表模式**：结构化字段（外貌、性格、背景、语言风格等），引导你构建完整角色
- **自由编辑**：直接写提示词，适合高级用户
- **AI 随机生成**：一键生成随机角色，或基于已有信息智能补全

还支持从 Wiki 长文本批量导入角色。

### 6. 本地优先，隐私可控

所有数据（角色卡、聊天记录、API Key）存储在本地设备。没有云端同步，没有数据收集，你的故事只属于你。

## 技术栈

| 层级 | 技术 |
|------|------|
| 框架 | React Native (Expo ~54) |
| 语言 | TypeScript strict mode |
| 状态管理 | Zustand |
| 存储 | expo-sqlite (Native) / localStorage (Web) |
| LLM 接入 | OpenAI 兼容 API（支持 Ollama、LocalAI 等） |
| 测试 | Jest 29 + ts-jest |

## 快速开始

```bash
npm install
npx expo start          # 移动端
npx expo start --web    # Web 端
npx jest                # 运行测试
```

## 项目结构

```
src/
├── components/     # 共享组件（LoreEntryCard 等）
├── constants/      # 主题常量
├── hooks/          # 自定义 hooks（useTheme）
├── navigation/     # 导航配置
├── screens/        # 页面（舞台、图鉴、世界观、设置）
├── services/
│   ├── api/        # LLM 客户端、提示词组装、压缩
│   ├── db/         # SQLite DAO（角色、消息、舞台、世界观）
│   ├── scheduler/  # 发言调度（提及检测、提问检测、活动权重）
│   └── export/     # Markdown 导出
├── stores/         # Zustand 状态管理
├── types/          # TypeScript 类型
├── utils/          # 工具函数（环境色、触觉反馈）
└── __tests__/      # 测试用例（79 个）
```
